# The department map: where things are and who writes them

Kept out of `AGENTS.md` so every lane's hot chain stays small. Read it when you need a path or its writer;
AGENTS.md links here. All paths are relative to the user's data folder.

| Path | What | Writer |
|---|---|---|
| `profile/` | the corpus, `evidence.yaml`, intake notes: every fact about the owner, with evidence ids | corpus-keeper (new work enters through `add-experience`); others read |
| `profile/PROFILE.md` | the finalized master profile every writer selects from; `PROFILE-HOLDS.md` its must-not-add list | profile-editor |
| `profile/facts.yaml` | canonical names, dates, titles, degrees, links; `conflicts:` open or ruled | the owner rules; the corpus-keeper records; agents propose |
| `profile/private.yaml` | the owner's own answers for application forms (salary, relocation, remote, notice, legal name, EEO); gitignored | the owner only; agents read it |
| `resumes/bases/general/` | the one base resume: every variant copies it (`base_of: general`); frozen, hash-pinned (`SHA256.txt`); no base per lens | changes only on the owner's word: resume-tailor (`build-resume-base`), editor re-sign, the owner approves |
| `resumes/variants/<application>/` | tailored resume (lens = emphasis label) + PDFs + ats-report + review | resume-tailor, resume-editor |
| `jobs/` | normalized postings | scripts/fetch_ats.py, job-scout |
| `targets/platforms.yaml` | every job platform: what its terms allow (API, alert mail, browser with the owner, manual), alert setup, yield | platform-scout |
| `applications/<slug>/` | jd, fit, application (event log), outcome | fit-scorer, tracker-ops |
| `applications/<slug>/HUB.md`, `state/role-hubs.md` | the per-role record: a generated join of opening, company, people, trail, events, variant, fit, research, prep and legal, with `missing:` lines; the index lists companies with a trail and no application | `scripts/role_hub.py` via `dashboard.py`; never hand-edit |
| `pursuits/<slug>/pursuit.md` | one direction into a company (a referral through one person, direct, a recruiter's inbound): its people, the owner's picks, the master resume, stage, `waiting_on`, next action; `## Strategy` and `## Decisions` (each citing the owner's ruling or words) and `## Log`, append-only | the Recruiter, only through `scripts/pursuits.py` |
| `pursuits/<slug>/HUB.md` | the pursuit's generated join: people, intake and case, company and legal check, each pick with its role hub, the master resume, outreach and approvals (never message text), one timeline | `scripts/pursuit_hub.py` via `dashboard.py`; never hand-edit |
| `applications/<slug>/apply-pack.md` | the apply pack: every form answer copied from a record, with its source; gitignored | apply-assist, only through `scripts/apply_pack.py build` |
| `state/accounts.yaml` | which job portals the owner has an account on; never a credential | apply-assist, only through `scripts/apply_pack.py account` |
| `prospects/` | the CRM, one file per person | inbox-harvester, prospect-triage, messenger, prospector |
| `touches/YYYY-MM.jsonl` | every message in or out | scripts only (append) |
| `companies/` | company dossiers; the dossier's `slug` (and its `aliases:`) is the company's one slug: `scripts/company_index.py` resolves every spelling to it for every writer and join, `scripts/company_slugs.py check` finds drift | company-researcher |
| `outbox/` | drafts waiting for the owner | messenger, prospector, linkedin-editor |
| `prep/` | STAR bank, prep packs, debriefs | prep-coach |
| `legal/` | visa timers, unemployment ledger, employer checks | legal-visa |
| `clock.yaml` | the job clock: last working day, new start, visa allowance | `scripts/clock.py set` only (the Recruiter records the owner's dates on their word; legal-visa the DSO-confirmed allowance) |
| `playbooks/` | how-to pages: `outreach.md` (message library), `send-after-yes.md` (the one post-yes send step), `portals/<portal>.md` (each portal's specialist) | the Recruiter; portals: platform-scout and the apply lane |
| `state/recruiter/` | the day: `sweep-<date>.md`, `cards-<date>.md`, `queue-<date>.yaml`, `wrap-<date>.md`, `LESSONS.md` | the Recruiter, through `recruiter_sweep.py`, `cards.py`, `day_queue.py` |
| `scripts/` | deterministic tools (tested) | engineering only |
| `DASHBOARD.md` | generated by `scripts/dashboard.py`; never hand-edit | script |

Obsidian views (views/*.base) are read-only lenses; the files are the truth and the scripts write the data.
